# 亡灵之塔：美术与界面方向

日期：2026-09-17。状态：方向提案。本轮只增加本文，不修改游戏源码、样式、数值与素材。像素尺寸、配色及数量是建议规格，后续原型检验后再定稿。

承接 [亡灵诸族主题与玩法映射](./亡灵之塔-增量玩法迁移设计.md)：骷髅、僵尸、幽魂、吸血鬼、尸巫、死亡骑士、骨龙、灾厄领主构成军团；亡灵术士与通灵议会负责施法体系。

## 1. 推荐方向

**采用“暗黑像素墓园＋可视军团＋双栏经营台”。桌面默认左侧显示高塔与战场，右侧操作军团、研究和升级；顶部统一显示资源与章节。**

定位是一款能看见军团成长的深度增量游戏。美术目标是粗粝、克制、有辨识度：古老墓园、倾斜墓碑、破败城门、稀疏魂火、沉默的队列。角色使用低分辨率轮廓、少量颜色和短动画，依靠姿势与剪影塑造身份。

观看负责吸引人停留，操作负责让成长持续。两者同屏，玩家购买第一位尸巫时，应当既看见数值变化，也看见它走入军团、举杖并释放第一道死亡法术。

## 2. 为什么这样选

下表是针对本项目的设计判断，不是对参考作品的质量评分。Cookie Clicker 的比较采用本轮提出的三栏范式；其视觉参考可从 [官方商店截图](https://store.steampowered.com/app/1454400/Cookie_Clicker/) 查看。Antimatter Dimensions 的比较来自本地 `src/components/tabs/` 和 `src/components/ui-modes/`：购买行、分系统标签与数值阅读是可借鉴的基础。

| 方案 | 对本作的价值 | 在本作中的主要代价 | 结论 |
|---|---|---|---|
| Cookie Clicker 式三栏 | 观看、资源反馈和购买可以并行 | 三个常驻区域争夺宽度；大点击物没有对应的既定玩法；后期研究和装备需要更大操作区 | 借鉴即时反馈与可见成长，不照搬三栏分工 |
| AD 式数值和标签页 | 多层重置、研究树、挑战信息容易组织；清楚、紧凑 | 如果画面仅有数值，无法充分展示亡灵种族与军团成长 | 保留操作组织方式，用作经营面板 |
| 战场全屏、操作浮层 | 首次印象鲜明，军团很突出 | 高频购买和数值比较要反复开面板；战斗素材和演出需求容易扩大 | 作为可选观战模式，不做默认首页 |
| 高塔剖面、每层一个房间 | 与“塔”关联强，建设变化明显 | 容易让人以为玩法是分房间建造、工人调度；层数巨大后难对应原系统 | 用作背景和阶段形态，不作为所有操作入口 |
| **左战场、右经营双栏** | 军团常驻可见；经营保留足够宽度；可以逐步丰富表现 | 需要让动画与成长对应，控制后期信息量 | **推荐为默认结构** |

三栏结构以后可在超宽屏加入可折叠的事件记录，但不作为必需布局。默认不设置巨大的“点击高塔获得游魂”按钮：当前玩法映射以生产和购买为基础，反复点大图会改变玩家对核心循环的预期。

## 3. 桌面首屏

以下为信息布局示意，文字与空白不代表最终视觉稿。

```text
┌──────────────────────────────────────────────────────────────┐
│ 亡灵之塔    当前章节       游魂 / 每秒产出       魂印   设置   │
├────────────────────────┬─────────────────────────────────────┤
│                        │ 军团  议会  祭坛  研究  更多          │
│   墓园、高塔与远方天空 │─────────────────────────────────────│
│                        │ 当前产出说明          单购 / 十购 / 最大│
│   骷髅、僵尸、幽魂     │ 骷髅兵     数量    倍率        [召唤]│
│   尸巫施法，骨龙掠过   │ 僵尸       数量    倍率        [召唤]│
│   前线与来敌短暂交锋   │ 幽魂       数量    倍率        [召唤]│
│                        │ ……                                  │
│────────────────────────│─────────────────────────────────────│
│ 观战 / 暂停 / 显示设置 │ 本次筑塔收益与要求          [筑塔]   │
│ 下一目标与一条关键消息 │ 拓展墓域收益与要求          [开辟]   │
└────────────────────────┴─────────────────────────────────────┘
```

建议桌面宽度达到约 1200px 时采用双栏。左侧约三分之一，优先保证 384–448px 的可用场景宽度；右侧占剩余空间。比例是试排基线，不硬锁百分比。顶部控制在两行以内，避免标题、说明和装饰占掉首屏。

### 左侧：一个活着的墓园

- 上部是高塔剪影、墓园设施和章节天空；中下部是军团及小规模交锋，组成同一个场景。
- 能看到当前已解锁单位的代表，而不是把所有数量逐只画出。第一只新单位必定登场，重复购买达到增长档位时才增加代表数量。
- 点击单位可以高亮右侧对应购买行；悬停或键盘聚焦可看名称与数量。场景不承担唯一的购买、重置入口。
- 下方只显示“下一项可达目标”和一条最近的重要事件，避免滚动新闻持续抢注意力。
- 暂停动画只停止表现，不停止生产。按钮明确标作“暂停动画”。

### 右侧：紧凑的指挥台

- 八阶军团采用连续列表：小立绘、名称、当前数量、主要倍率/产出、价格和购买按钮。列对齐，价格长了也不能挤走按钮。
- 单次、十次、最大购买使用一个统一控件，自动化设置放在同一行的次级入口。
- 升级按原系统和前置组织；大批一次性升级可以用紧凑矩阵。研究树与装备使用各自适合的布局，不强行全部改成购买行。
- 筑塔、墓域、转生等动作显示收益与重置摘要。当前相关动作放在面板底部独立区，和普通召唤拉开距离。
- 解锁后才出现对应导航。后期按“军团与生产 / 研究与挑战 / 冥器与遗赠 / 主宰与终焉”分组，避免把所有子系统铺成一排标签。

研究树或复杂装备页可以把场景收成窄幅“观战条”，让操作区扩展；返回军团页恢复双栏。用户也可主动关闭场景，获得纯经营视图。

## 4. 军团如何战斗，如何让人愿意看

### 初版：与状态关联的战斗演出

场景显示真正的交锋动作：近战单位前移、挥击、回位；尸巫抬杖施法；幽魂穿过前线；敌方守卫被击中后溃散。战斗以短演出循环组织，避免做寻路、碰撞、复杂 AI 和独立战斗结算。

**经济状态是真实的，战斗表现是抽样的。**解锁、升级、挑战和重置驱动可见变化；敌人溃散不额外产生资源，军团动画倒地不减少已拥有的单位。第一版不显示虚构的精确伤害、击杀收益或敌方生命条，避免玩家误判收入来源。

保留真实的游魂产出数字；飘出的魂光只表达资源流入方向，不写“击杀 +100 游魂”等不存在的奖励。隐藏、减速或暂停场景，都不影响产速和离线收益。

| 玩家操作 / 状态 | 画面反应 | 增量机制关系 |
|---|---|---|
| 首次召唤骷髅 | 墓土裂开，一具骷髅加入前线 | 表示 AD1 解锁与购买 |
| 解锁僵尸 | 腐土墓穴开启，缓慢的新轮廓进入队列 | 明确新种族出现 |
| 解锁尸巫 | 阵后出现法师位置，首次释放绿焰法术 | 明确高阶单位参与生产链 |
| 解锁骨龙 | 场景上方出现龙翼剪影与短促吐息 | 用体型与垂直层次表现地位 |
| 批量召唤 | 对应族群的代表队列扩充、队旗强化 | 按显示档位抽样，不能一购一精灵 |
| 筑塔 / 墓域增长 | 高塔模块、城墙、墓地或旗帜发生变化 | 对应实体筑塔和领地状态 |
| 灵魂献祭 | 代表单位化作魂光，汇入仪式中心后重新组织 | 按实际重置结果更新阵容 |
| 转生 / 轮回 / 创世 | 不同级别的魂流、天空变化和场景重建 | 保持可跳过；收益与损失仍由面板说明 |
| 进入挑战 | 对应封印、枯萎、沉默或迟滞效果出现在场景 | 对应真实限制；不只靠换背景颜色 |
| 完成重大里程碑 | 增加一处永久视觉标记或新地貌 | 给长期成长留下可见记忆 |

动画速度设上限。哪怕游戏速度已达到极高倍率，战场也维持可辨认的步伐；用更多魂流、阵型规模、法阵和背景层级表达强度，不能真的每秒播放数万次攻击。

### 兴趣来自三类变化

1. **认出新单位。**先看到未知剪影，再解锁它的外形与动作；无需每次购买都弹大窗口。
2. **看见势力扩张。**最初一片荒坟，后来出现议会、骑士旗帜、龙墓，再进入疫土、冥河和终焉天空。
3. **同一队伍产生不同气质。**研究路线和所在领域影响队旗、法术主色、站位重心与环境；只改变表现，不额外叠加属性。

敌方首批只需要两种剪影，例如持盾守卫与火炬巡逻者。后续章节可换为圣堂军、封印投影等，但不必为每个研究或挑战单独绘制敌人。尸巫射击、死亡骑士突进等先用于演出识别，战术差异留给以后独立设计。

如后续希望加入真正的战斗、敌人血量、关卡和战利品，应单独做玩法决策与经济验证。当前方向能在保留 AD 增量公式的条件下先实现“有军团在战斗”。

## 5. 低技术力像素的具体边界

“低技术力”指生产负担低、表现规则简单且一致，不等于角色难以辨认。建议采用正侧面或轻微侧转视角，分前后两排站位；只绘制一个主要朝向，需要时镜像。避开等距八方向、骨骼蒙皮、写实打光和连续大幅运动。

| 项目 | 建议规格 | 目的 |
|---|---|---|
| 场景内部画布 | 起步约 192×160 像素 | 2 倍显示约 384×320，适合桌面左栏 |
| 地面与建筑模块 | 16×16 像素网格 | 墓碑、门、墙、塔身可以拼接复用 |
| 普通单位 | 16×24 或 24×24 像素画布 | 身高与姿势有差异，制作量可控 |
| 大型单位 | 32×32 或 48×32 像素画布 | 骨龙、领主等保留轮廓优势 |
| 普通单位颜色 | 通常 4–6 色，共享阴影色 | 通过配件和姿势区分，控制碎色 |
| 待机 / 行走 / 攻击 | 分别约 2 / 4 / 3–4 帧 | 允许短停顿和有力关键帧 |
| 受击 / 消散 | 1 帧闪色，2–3 帧通用消散 | 多种单位共享表现 |
| 动作帧率 | 建议约 6–10 帧/秒 | 低帧像素动作，不追求平滑插帧 |
| 同屏代表单位 | 初版目标约 12–20 个，含敌方 | 属于设计预算，需实际测性能与拥挤程度 |

使用最近邻放大、硬边像素和完整色块；场景尽量按整数倍缩放，尺寸不够时调整可视范围或留出装饰边，不任意拉伸像素。移动端优先另设横向浅景构图，沿用同一批角色与地块。

可以用共用的位移和颜色变化补充短动画；大型单位不需要连续飞行，只用落地待机、短翼振和一次吐息。避免给整幅场景加模糊、密集噪点、CRT 扫描线或连续屏幕震动。

### 八阶单位的识别重点

| 单位 | 第一眼的识别点 | 适合的廉价动画 |
|---|---|---|
| 骷髅兵 | 苍白窄身、短兵器、松散骨架 | 两步摆动、举刀挥击 |
| 僵尸 | 宽肩、垂臂、弓背、腐绿局部 | 拖步、前扑 |
| 幽魂 | 无腿、破布下摆、冷青轮廓 | 上下浮动、短距离穿梭 |
| 吸血鬼 | 深色斗篷、红色领口、直立姿态 | 斗篷开合、短促突进 |
| 尸巫 | 高冠或兜帽、长杖、仪式袍 | 抬杖、浮起法球 |
| 死亡骑士 | 厚重盔甲、长武器、破损战旗 | 沉重迈步、横斩；初版可不制作坐骑 |
| 骨龙 | 长颈、翼架、横向大轮廓 | 翼振、低头吐息 |
| 灾厄领主 | 高大身形、残冠、悬浮碎片 | 低频抬手、脚下法阵亮起 |

敌我轮廓、位置和动作方向都要可区分，不单靠红绿颜色区别。像素单位保持严肃比例，头部适度放大保证辨识，但不走圆滚、可爱表情和滑稽蹦跳路线。

## 6. 暗黑美术基调

关键词：**荒坟、旧铁、腐木、灰骨、暗血、磷火。**背景大面积低饱和；亮色集中在眼睛、魂火、符文和关键操作。暗黑感来自轮廓、留白与材质，界面正文仍需清楚可读。

以下是候选色板；值按角色集中定义，尚未写入项目 tokens。

| 颜色角色 / 建议 token | 候选值 | 使用方式 |
|---|---|---|
| `--color-background` | `#151917` | 主背景，偏绿的黑灰 |
| `--color-surface` | `#202621` | 控制面板与墓园暗部 |
| `--color-border` | `#465047` | 边框、分隔与石材亮面 |
| `--color-text` | `#E2DECD` | 主文字、重要数值与灰骨亮面 |
| `--color-muted` | `#ADB1A3` | 次级说明，仍需验证对比度 |
| `--color-accent` | `#A4BD79` | 可购买、魂火与当前选中状态 |
| `--color-blood` | `#BC7376` | 血族与危险说明的有限强调 |
| `--color-spirit` | `#7DAEA6` | 幽魂与时间系统的局部识别 |
| `--color-relic` | `#B8A374` | 古物、里程碑与永久奖励 |

低饱和暗红不能直接用来写很小的警告文字。正式样稿要测正文、按钮、禁用状态的对比度；焦点与可点击状态通过线条、图形和文字同时表达。以上色板是起点，不声称已完成可访问性检验。

界面建议采用薄直角边框、少量切角、石板与旧铁质感。纹理放在边缘或背景，不覆盖数字。按钮形状保持简单，用明暗边和短暂按下位移反馈操作；避免每个模块都是厚边框、骷髅雕花和发光描边。

**文字与数值保持清晰。**标题、少量英文标记和装饰数字可尝试像素字体；长篇中文描述采用清晰的常规中文字体，数值采用等宽数字。字体候选待字库覆盖与显示测试后确定，不让整页中文变成难读的小像素方块。

## 7. 如何承载后期系统

767 条映射是长期内容清单，不需要 767 张独立立绘。图形资产按“单位、资源、系统、环境”组织，升级主要通过系统图标、名称、节点形状和状态区分。

| 进度 | 场景变化 | 经营界面变化 |
|---|---|---|
| 起步 | 荒坟、单座残塔、少量骷髅 | 军团、魂火、筑塔与墓域 |
| 转生与破界 | 墓园扩张、城门亮起、更多族群进驻 | 转生魂契、通灵议会、瘟疫 |
| 轮回与永夜 | 天空变化、祭坛点亮、幽魂与仪式增多 | 冥典树、挑战、祭坛与永夜 |
| 创世与冥器 | 高塔轮廓重构、不同冥器影响局部演出 | 冥器、遗赠、双钟与脚本 |
| 主宰阶段 | 主宰旗帜、领域背景、特殊阵容重心 | 各领域各有入口与识别图形 |
| 终焉 | 场景逐步失色、裂隙吞没背景、火光恢复 | 保留操作位置，以状态变化表现压迫 |

第几层塔用真实数字显示，背景只显示阶段形态。增长到数万层时，不生成数万个楼层。背景建筑与军团代表是压缩表达，面板上的数量和效果才是精确记录。

首批至少让解锁军团、筑塔和转生发生可见变化；仅换天空颜色不足以支撑完整成长体验。

## 8. 小屏与长时间游玩

- 窄屏改为顶部资源、浅景军团、经营面板的上下结构。场景可折叠；不把双栏硬挤进手机。
- 操作页面保持单页纵向阅读，避免场景和经营区各自出现小滚动框。
- 研究树用“树图 / 节点列表”切换解决窄屏阅读；页面根容器不依赖横向滚动，树图的平移缩放限定在明确区域。
- 场景默认静音；提供减少动态、关闭闪光与关闭场景选项。尊重系统减少动态偏好。
- 新生单位登场和重置演出不锁住高频操作；连续自动重置时合并表现，不重复全屏播放。
- 可交互单位同时有列表入口；提示可通过点击或键盘打开，不依赖悬停。
- 后续原型应检查 320、375、414、768px，以及 1280/1440px 桌面宽度。本轮为文档，没有完成这些渲染检查。

## 9. 首批素材与验证顺序

先做能判断方向的小样，再扩充素材。下表是制作范围建议，不是工期承诺。

| 批次 | 内容 | 判断什么 |
|---|---|---|
| A：静态风格样张 | 一个墓园场景、骷髅/僵尸/尸巫三个角色、一个资源栏、三条购买行 | 暗黑但可读，低像素也认得出不同族群，左右比例合理 |
| B：短战斗样张 | 三个角色的短动作、两个敌方剪影、一次法术与消散 | 战斗能看懂，循环有节奏，普通电脑浏览器可承受 |
| C：首屏成长样张 | 从少量单位到混合军团、一次筑塔、一次转生 | 玩家看得见购买带来的变化，动画不会遮挡经营 |
| D：完整第一组军团 | 补齐八阶角色和对应图标 | 尸巫、黑骑、骨龙和领主值得期待 |
| E：系统扩展 | 议会、祭坛、冥器和主宰的共享视觉模板 | 复用资产仍能区分系统，后期不拥挤 |

首轮不绘制八阶单位的所有升级变体，不画全部主宰大立绘，不做数十个背景、不上复杂粒子或实时光照。先把“购买一位尸巫，左边真的出现一位尸巫并施法”的体验做扎实。

实际实施时，模拟内核负责生产，场景只订阅必要状态。场景推荐单一低分辨率绘制层，按钮和表格保持标准界面控件；不为屏幕外的巨量单位创建渲染对象。具体渲染技术留到原型阶段选择，本轮不引入库。

## 10. 方向验收标准

1. 看静态截图能认出亡灵军团与墓园，至少骷髅、僵尸、尸巫三种单位不靠文字也可区分。
2. 首屏同时容纳有意义的战场与主要购买操作，不需要先看完整段动画才能经营。
3. 首次解锁与关键成长能产生明确的视觉变化，纯粹重复播放的背景不算完成。
4. 关闭动画后，全部经营操作与实际收益一致；页面没有虚构伤害或掉落诱导。
5. 研究、挑战和大数仍读得清；资源升级后，列表列宽与操作位置稳定。
6. 暗黑风格下仍能辨认正文、按钮、键盘焦点和异常状态；小屏可关闭或收起场景。

下一步最有价值的交付是 A 批次静态风格样张，用它检验画风、角色轮廓和左右比例，再决定是否进入动态原型。本提案本身不代表样张或战斗已经实现。

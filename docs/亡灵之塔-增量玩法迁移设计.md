## 1. 迁移结论

可以把原作从初始生产到终局的完整增量结构迁移为“召集亡灵军团，筑起高塔，以转生与轮回积蓄力量，重铸冥界，最终挣脱终焉封界”。建议第一版保留原作数学与解锁图，替换玩家可见的名词、叙事、资源图标和界面组织。平衡改动放在能够完成全流程之后，单独记录差异。

这是具有多层重置、生产链、自动化、挑战、装备构筑和终局规则变化的增量游戏。将全部资源改叫“灵魂”、将八阶单位改成八个攻击力等级，都会破坏原有资源边界。现阶段也不添加关卡战斗、敌人生命、装备掉落战斗或离线杀怪；这些会引入原作没有的消耗与时间模型。

**主题约定：**玩家是掌管高塔的亡灵术士。亡灵军团由骷髅、僵尸、幽魂、血族、尸巫、死亡骑士、骨龙及灾厄领主组成；通灵议会召集不同专长的施法者；墓园祭坛承载各族仪式；灾厄化身构成终局生产链。高阶存在通过统御、招魂和缔约召来低阶存在，保留原有生产关系。


### 第二版主题总纲：亡灵诸族与墓园王国

本版重新分配了军团、施法者、建筑、冥器和主宰的角色。骷髅是起步兵种，僵尸代表腐朽与瘟疫，幽魂代表灵魂与时间，血族代表鲜血契约，尸巫代表死亡法术，死亡骑士代表统御与誓约，骨龙代表远古亡灵，灾厄领主代表高阶统治。

《英雄无敌 III》墓园兵种及其升级形态为命名灵感，原作兵种表见 [墓园资料](https://heroes.wikioasis.org/wiki/Necropolis)。本游戏选用其中部分通行中文称谓，并增加原创施法者、灾厄领主与终局实体；下表是本游戏的八阶增量映射，不是《英雄无敌 III》的原版八级兵种表。死亡骑士在此作为本作单位称谓，僵尸等名称不强制与原作未升级形态逐级对应。

| 体系 | 原系统 | 第二版主题 | 设计职责 |
|---|---|---|---|
| 亡灵军团 | AD1–8 | 骷髅兵、僵尸、幽魂、吸血鬼、尸巫、死亡骑士、骨龙、灾厄领主 | 让玩家从墓地招魂发展到统御亡灵诸族 |
| 通灵议会 | ID1–8 | 守墓侍僧、招魂师、诅咒祭司、亡灵术士、灵魂编织者、瘟疫使者、死亡贤者、永恒巫妖 | 用不同施法传统承接第二条生产链 |

| 灾厄化身 | DMD1–4 | 憎恶聚合体、瘟疫巨像、恐惧收割者、终末使徒 | 呈现终局的异变、瘟疫、恐惧和毁灭 |

升级采用“所属体系＋具体效果”的命名。基础升级使用招魂、尸骸复苏、血契、亡灵统御等词；研究使用通灵、诅咒、献祭和瘟疫；天赋使用遗赠、传承和不朽；末日升级使用末世、残存与复苏。亡灵术士同时是玩家职业与议会第四阶的职业名，界面明确区分“塔主”与“议会成员数量”。

**关系示例：**骨龙受灾厄领主召集，死亡骑士受龙威与古老誓约唤醒，尸巫由骑士护送至高塔，吸血鬼与尸巫缔约，幽魂被血族仪式召来，僵尸由幽魂附体，骷髅从墓地收集游魂。这是生产链的叙事解释；兵种不会消耗上阶数量，也不会在数值上互相进化。死亡骑士、尸巫和骨龙的战斗特征作为文案灵感，不额外引入伤害、吸血或战斗掉落倍率。

骷髅勇士、吸血鬼王、尸巫王、恐怖骑士、幽灵龙等名称可作为对应族群的称号或未来外观。当前不添加没有原始升级 ID 的分支进化；不能把 AD7 骨龙额外升成 AD8 幽灵龙后再把灾厄领主塞成 AD9。灾厄领主是可招募的第八阶单位，灾厄君主是独立主宰角色；终末使徒是第四灾厄化身，死亡化身是终局主宰，避免混淆。

原 `gameLoop` 明确先执行自动购买，再更新相关缓存；生产顺序为 Time Dimensions → Infinity Dimensions → Antimatter Dimensions，然后处理免费 tickspeed、复制、膨胀等。真实时间系统与加速游戏时间系统分开。调整这个顺序会改变同一 tick 内的资源与重置结果。`Effects` 的相乘、相加、取最大、取最小、幂运算也不能统一改成一个“总倍率”。

### 完整性口径

767 是配置条数，不是“升级总数”：其中包含 12 个灌注形态、144 个普通成就、32 个秘密成就、25 个速通节点以及 20 条自动机命令/帮助。实际可购买项数量必须按类型统计。

“所有等级”采用两种表达：有限等级列出完整值；可重复增长的等级给出 `n → n` 的对应规则与原成本函数、封顶、软上限。不会把没有固定终点的升级武断裁成十级。原作程序可表示的有限上限仍然保留，不把 `Number.MAX_VALUE` 当成数学无穷大。

新闻全文、天神对话全文、教程全文、皮肤颜色并非升级，本文确定其主题归属与依赖入口，不声称已经完成全部文案创作。付费商品、云账号和 Steam 成就同步是外围服务，完整单机增量流程以无付费加成的基线为准；不复制原服务账号或凭据。

## 4. 全流程阶段与解锁关系

这些“章”是界面导航层次，不增加数值门槛。

| 章节 | 原阶段 | 亡灵主题 | 主要入口 |
|---|---|---|---|

天神不是七次普通线性 prestige。进入领域通常借用创世重置，但每个领域有自己的限制与永久奖励；先祖记忆、炼金、虚冥会跨章节持续发挥作用。

### 先祖追忆：100 个等级与八条强化轨道

四位先祖分别 1–25 级；未解锁记为 0，不能把 0 当作第一级。每位先祖都有“追忆滋养”及“残片凝聚”两条重复升级：

| 原项 | 新项 | n 次购买后的倍率 | 下次追忆费用 |
|---|---|---|---|
| memoryUpgrades | 追忆滋养 | 1.3^n | 1000×5^n |
| chunkUpgrades | 残片凝聚 | 1.5^n | 5000×25^n |

升级费用达到 24→25 所需经验的 50% 时禁止继续购买；按本基线公式，滋养可购 n=0…22，凝聚 n=0…11（n 是已购次数，最高状态不能再购）。每个先祖独立花费自己的追忆，不能把四人经验合并。聚焦追忆（Remembrance）改称“追忆凝视”：四位先祖总等级达到 20 时开放，所选先祖残片生产 ×5，其他先祖 ×0.5。

原等级 l→l+1 费用：`floor((l+l²/10)^5.52 × 1.5^max(0,l−15) × 1e6)`，l=1…24；到 25 级停止升级。炼金配方解锁按遗物典藏官记忆等级，不能使用四人等级和。

## 13. React 迁移方案与验收

### 模块边界

建议目标结构分成 `simulation`（时间循环与生产）、`mechanics`（购买、重置、挑战）、`content`（ID、配置和主题文本）、`save`（版本化存档）、`automation`（自动机与脚本）、`ui`（React 订阅视图）。这是后续实施建议，本次没有创建这些代码。

保留原 Decimal 等价运算和序列化；普通 JS number 不能承载游魂/魂印/冥印的后期数值。原项目使用 `break_infinity.js`，但依赖一个大数库还不够：常量、Math 扩展、Effect 顺序、缓存失效、状态集合、事件和公式都要一起移植。

不要直接把原 `player` 塞进 React state，并在每次购买时复制整个对象；用独立状态内核和稳定的 UI 快照订阅。存档新增游戏标识和版本，保留原 ID 为追踪字段；若以后提供原作存档导入，单独做可验证的转换器，不把新主题存档写回原游戏。

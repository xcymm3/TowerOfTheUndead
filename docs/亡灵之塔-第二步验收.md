# 第二步：初期界面与操作验收

## 界面约定

沿用已确认参考图的暗石板、旧铁边框、魂火绿、金色数值和八族像素素材。用户最新更正：桌面左侧为经营面板，右侧为军团场景；窄屏上下排列。实现与测试已同步为左经营右军团，移动端经营在前；当前仍待完整重新验收。保留现有字体和色彩变量，不引入新的主题、敌人或战斗收益。

实际场景读取原作维度数量，按数量级展示代表队列；名册显示真实格式化数量。场景暂停只停动画。重置后，失去的单位从场景移除。

筑塔、墓域和转生的展示组件继承原作组件的数据更新、条件及操作方法，只替换模板和无障碍禁用状态。需求数量、倍率、重置收益和批量购买仍来自原作；Shift 点击行为继续保留。

经营面板将重置条件和效果放在操作按钮之外；初期说明使用映射名称。最大购买的价格标注为单次起价，并以原作“可补至下一组十次”的条件启用。

## 测试方法

`tests/early-interactions.mjs` 接入 `pnpm test:runtime` 和 `pnpm test`。阶段夹具只提供资源、单位数量或进度，之后通过 Playwright 点击真实控件。固定原作构建提供状态对照；不以主题版自己计算的结果作为唯一预期。

新增检查范围：

1. 单次、资源不足时补十、跨十次边界与最大购买；对照原版价格、数量及倍率。
2. 筑塔需求前一单位与恰好满足条件的边界；逐次取消/确认四次筑塔，再实际召唤到第八阶。
3. 八阶各自不足价格及恰好价格购买、逐阶筑塔重置保留项对照；魂火节律不足/恰好费用、单次和最大购买与原版对照。
4. 首个墓域需求边界，取消/确认及重置后军团同步。
5. 献祭取消/确认，倍率、保留第八阶及移除低阶军团。
6. 首次转生门槛，强制确认、取消、收益与原版对照。
7. 320、375、414、768、1024、1440 宽度下的排列、重置按钮可达性及展开经营切换。

首次转生用例还覆盖快速转生成就提示及延迟动画说明：先用超过一分钟的阶段夹具完成首次转生并关闭动画说明，再通过原作第 55 号成就的解锁回调检查快速转生提示。两条提示分别验证 320px 下的边界与关闭操作，避免原作共用消息弹窗在两条提示同时触发时相互覆盖，造成测试时序误判。布局检查要求没有未处理弹窗，并通过点击位置命中检查，避免只检查元素存在而忽略遮挡。

## 截图复查后的修正

- 覆盖原作弹窗的固定最小宽度，中文标题与正文随窄屏换行。
- 翻译首次转生的两条提示，以及普通 DOM 通知中的映射术语；保留通知触发条件、时长和关闭行为。
- 通知采用既有暗色面板和金色边线，移除与参考风格不符的亮黄色背景。
- 窄屏资源栏压缩数字字号，科学计数法示例 `1.00e100` 不再折成两行；达到原作转生上限时，资源栏显示 `∞`。
- 拍摄布局截图前恢复页面滚动位置，排除操作测试遗留状态。

本轮构建遇到开发机内存不足导致的明显延迟，运行时构建改为 `parallel: false`，降低编译进程并发；不修改任何游戏内时间或模拟参数。

八阶解锁测试不是从新存档按正常时间完整等待至首次转生；它验证原条件下的真实操作和状态结果。完整长时间推进仍由第 5 步验收。

## 验证结果

Deadline-Carl build 已修正左右布局并执行当前运行时回归、正式构建与子路径购买/名册/保存刷新测试。开发结果在当前迭代 scratch 的 runtime-report.json、production-report.json、build.log 与六宽度截图中；正式 proof 与独立验收仍由后续 evidence/verify 阶段负责。

参考图逐项复查：保留墓园、八族像素素材、暗石板配色、金色数字和绿色购买按钮；实际边框更简洁，数值和重置条件采用原版而非美术占位。移动端经营优先，重置按钮通过 iframe 滚动可达。临时成就通知等待原定时长消失后截取布局，不改变游戏通知行为。

限制：原版节律悬浮提示仍含 Purchased Upgrades 英文，留待全量文案审计；41 页渲染仍是强制阶段夹具，不能代替后期系统操作证据。GitHub CLI 认证失效且 Pages API 返回 HTTP 403，尚未发布或证明线上可访问。

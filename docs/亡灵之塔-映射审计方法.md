# 映射与界面审计方法

运行 `tests/runtime.mjs` 中的 `767 mappings bind to their original config objects` 用例，会在 `TEST_OUTPUT_DIR` 输出 `mapping-audit.json`。不设置 `TEST_OUTPUT_DIR` 时默认写入 `test-results/`。报告必须恰好包含 767 个唯一 `mappingKey`，并保留来源组、键、ID、文件与行号、原始字段表达式、主题名、运行时配置对象、显示路径和语义证据。

## 逐项显示检查

每项按其原版真实渲染方式选择一种检查路径，不用“对象已绑定”代替“页面可显示”：

- `configuration-field-prefix`：无独立标题的配置在原说明、奖励、要求或提示字段前显示主题名；字符串、函数与 getter 分别登记包装器。
- `component-context-name`：成就、V 解锁、追忆、炼金和征程里程碑按实际 Vue 组件翻译名称。同名的 `Effarig` 与 `Replicanti` 不使用全局覆盖，避免跨系统误配。
- `render-time-name-translation`：不会充当逻辑键冲突的唯一名称在渲染时翻译，原配置 `name` 不变。
- `component-context-challenge-name`：12 个轮回试炼入口按 `ECTimeStudy` 的实际组合标题检查。
- `derived-glyph-name-translation`：冥器类型按原版派生名称路径检查。
- `stable-cycle-name`：五条终焉裂隙保留原轮换数组和计时，只把轮换后的显示名固定为对应主题名。

最终报告要求每项 `displayStatus=PASS`，不得出现 `UNKNOWN`。当前实现会把未登记显示路径、目标名不一致或失效包装器直接记为 `FAIL`。

## 逐项语义检查

主题安装前保存每个原版配置对象的自有属性描述符。安装后只允许以下展示字段发生包装：

`description`、`reward`、`requirementDescription`、`singleDesc`、`totalDesc`、`hint`

其余 ID、名称逻辑键、花费、效果、需求、解锁条件、函数和对象引用必须保持相同。报告同时检查：

- registry 与生成的 `configurations` 是否仍为同一个原版对象；
- 主题名是否与固定索引一致；
- 字面 ID 是否一致；枚举表达式（如 `ALCHEMY_RESOURCE.POWER`）是否已解析为原版运行时 ID；
- 非展示字段描述符是否变化；
- 是否意外添加展示白名单之外的字段。

原配置没有显式 ID 时记录 `not-present-on-source-config`，由生成绑定的来源组和键确定对象，不把缺失字段伪造为 ID。最终报告要求每项 `semanticStatus=PASS`，且 `changedProtectedFields`、`unexpectedFields` 均为空。

## 数据库外文案与界面

`tests/content-ui-audit.mjs` 生成 `outside-database-content-audit.json`，分别检查：

- 核心资源、八阶军团与代表性动态说明；
- 帮助弹窗、搜索和实际帮助页；
- 通知 DOM、确认弹窗及按钮可操作性；
- 结局关键操作文案；
- Automator 编辑器、输入框、代码块和脚本语法保护；
- 创世律令、虚冥律令、冥器管理、死寂双钟、主宰星图和终焉面板。

六个后期页面逐一在 320、375、414、768、1024、1440 像素宽度检查页面溢出、根容器裁切、可见控件越界和小于 20px 的可操作控件，共 36 组。主题正文、次要文字和强调文字相对面板背景均按至少 4.5:1 检查。帮助正文保留原版完整规则说明，只替换主题术语与操作标题；Automator 语法、代码/公式、通用缩写及必要原版专有名词允许保留原文。

## 运行方式与边界

定向检查：

```powershell
$env:TEST_FILTER='767 mappings|Content audit'
node tests/runtime.mjs
Remove-Item Env:TEST_FILTER
```

第五步的定向结果不替代第六步约定的历史/损坏存档、全部备份类型、长离线、持续运行及原 15 项集中完整回归。原版源码仍由 `scripts/verify-source.mjs` 独立校验；第五步不运行 Deadline-Carl，也不发布 GitHub Pages。

# 存档与整体验收方法

`tests/storage-interactions.mjs` 由完整运行时回归调用。定向执行可设置 `TEST_FILTER='Storage'` 后运行 `pnpm test:runtime`；`TEST_OUTPUT_DIR` 指向本次证据目录。主题版与独立原版对照版运行在两个浏览器上下文，阶段夹具相同，存档、迁移、备份和离线函数均来自原版实现。

阶段资源、次数和临界值由测试显式赋值，不冒充自然游玩。边界动作使用真实界面或原版公开操作入口；比较报告保留夹具说明、主题版结果和原版结果。

## 存档覆盖

| 范围 | 操作与断言 |
| --- | --- |
| 历史格式 | 将当前有效玩家对象编码为创世版本以前使用的纯 Base64，并按旧单根结构写入本地存储；真实 `GameStorage.load()` 后检查内容保留且自动升级为三槽根结构 |
| 阶段语料 | 初期、中期、创世、主宰、终局五个代表状态分别执行当前序列化、反序列化和加载往返，逐字段与原版对照 |
| 损坏主存档 | 主根写入乱码后真实加载，检查安全回到新存档；随后从保留的自动备份界面恢复原状态 |
| 损坏输入 | 普通乱码、截断文本、缺少资源字段、NaN、损坏文件及损坏备份槽均不得改变当前有效状态 |
| 手动槽 | 三个存档槽写入不同资源和购买数，按 1→3→2→1 加载，检查隔离、刷新和原版一致性 |
| 自动备份 | 覆盖 1、5、20、60 分钟在线槽，10 分钟、1 小时、5 小时离线槽和保留槽；八槽均保存不同内容并逐一通过备份界面恢复 |
| 备份归档 | 点击原界面导出全部备份，清空八槽后从文件输入导入，检查八份内容和时间数据恢复；损坏归档被拒绝且不覆盖有效备份 |
| 命名空间 | 主题主存档、备份数据和备份时间键与原版完全隔离，主题上下文不写入原版键 |
| 长离线 | 24 小时初期状态执行“加速+跳过”，7 天后期代表状态执行“跳过”；两个上下文在相同批次边界调用原回调，检查资源、离散状态、5 小时离线备份和无挂起 |
| 关闭离线 | 7 天间隔关闭离线进度后不产生资源，单位购买状态仍保留 |

备份归档验收发现并修复了原版导入路径把时间数据写入不存在字段的问题。修复位于构建适配层，同时应用于主题版和测试对照版；上游源码未改，归档格式未改。长离线验收还修复了低 tick 数在首批同步完成时空进度对象不清理的问题：进度对象现在始终可渲染，并在未进入异步退出回调时执行同一收尾逻辑。两项修复都由源码校验限制为精确替换，不涉及玩法公式或数值。

## 跨阶段链

完整回归生成 `cross-stage-operations.json`，汇总三条连续链：

1. 新存档、购买、升层、墓园、献祭到首次魂界重置；
2. 破界、自动转生、疫种、研究、试炼、永夜到首次创世；
3. 七位主宰完成、封印、终焉、五次织机献祭、真实产量触发结局、字幕及新游戏继承。

每条链都列出夹具边界和对应运行时测试名称。完成标志、结局标志和织机阶段不得直接赋值。

## 持续运行与大数

`tests/performance-interactions.mjs` 包含两组验证：

- 三档大数和六档宽度检查：资源、八阶名册、购买、文字矩形、页面溢出、节点和精灵上限；
- 30 秒真实 `GameIntervals` 运行：每 5 秒采集资源、更新时间、外壳/内核节点和精灵数，检查时间持续推进、无进度阻塞、节点无界增长或超出 24 个代表精灵。随后打开终焉代表页面显示有限超大数，检查无 `NaN`、`undefined` 和横向溢出。

计时结果是同一机器上的验收观测，不宣称跨设备 FPS 基准。持续运行使用明确的后期夹具，不代表自然进度。

## 本地发布复核

完整回归后依次运行类型检查、lint、正式构建、正式产物冒烟和 `scripts/verify-local-acceptance.mjs <证据目录>`。最后一个脚本生成：

- `dist-manifest.json`：正式产物全部文件 SHA-256、子路径、引擎指纹和禁止开发文件检查；
- `cross-stage-operations.json`：三条跨阶段链；
- `local-ac-review.json`：原 AC1–AC14 本地部分逐条结论，AC15 标为 `DEFERRED_TO_STEP7`。

第六步不执行 Deadline-Carl，不部署 GitHub Pages。HTTPS 链接、线上资源、线上保存刷新和线上版本一致性只在第七步验收。

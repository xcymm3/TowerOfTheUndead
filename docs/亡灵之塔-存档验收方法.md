# 存档验收方法与限制

`tests/storage-interactions.mjs` 由完整运行时回归调用。定向执行可设置 `TEST_FILTER='Storage'` 后运行 `pnpm test:runtime`；`TEST_OUTPUT_DIR` 指向当前 scratch 目录。输出包括双方状态对照 `storage-operations.json`、浏览器实际下载的两份阶段存档和截图。测试存档仅写入 scratch，不进入正式产物。

主题与原版在独立浏览器上下文中运行，固定时钟、停止在线计时器。阶段资源由夹具赋值，不代表自然游玩所得；没有替换存档、迁移、离线或序列化实现。

| 范围 | 实际动作和断言 |
| --- | --- |
| 文件导出 | 点击原界面的文件导出按钮，捕获真实浏览器下载；使用下载内容作为导入输入 |
| 文本导入 | 打开原导入框，填入已下载存档并确认；资源、八阶单位、阶段次数、研究、原种子和冥器恢复，与原版相同 |
| 无效文本 | 普通乱码、截断存档、可解码但缺少资源字段、NaN 资源四类输入均无可用确认按钮；回车不能改变当前状态或已保存字符串 |
| 文件导入 | 实际上传损坏文件，确认状态保留；上传有效导出文件后状态恢复 |
| 多槽 | 经选择存档弹窗逐一操作三个槽，每槽不同资源和购买数；保存后按 1→3→2→1 顺序加载，检查隔离及原版一致性 |
| 自动备份恢复 | 夹具将原在线备份计时推进到一分钟并执行原备份检查；通过备份菜单实际恢复，再从预加载保留槽撤销恢复，检查两次资源结果 |
| 键空间 | 主存档、备份数据、备份时间键与原版不同；主题上下文不存在原版主存档键 |
| 离线 | 原序列化存档设定为 20 秒前，走真实 `loadPlayerObject` 离线分支；启用时产生资源，关闭时不产生，两边状态完全一致。此例为内核加载对照，不声称是 UI 操作；现有主测试另有真实刷新离线检查 |

离线对照在同一个 JavaScript 调用中结束同步补算并停止计时器，避免加载自动重启在线生产后，两页面执行时差引入额外资源。导入测试使用零生产量、非零购买数的静态单位夹具，专门检查存档字段保留；生产能力由独立离线用例检查。

当前未覆盖：历史版本存档样本与全部阶段兼容、损坏本地根存档的完整恢复、备份文件导入导出、全部备份时间档、长时间异步离线及加速/跳过、各后期领域的离线例外、跨阶段自然操作链及持续在线负载。桌面截图仍存在中英混排；存档测试中的人工高资源夹具未建立完整破界历史，因此该组截图的无穷显示不能用作有效后期大数排版验收。WI-010 仍未完成，本文不构成 AC11/AC12 的 PASS。

## 大数与响应基线

`tests/performance-interactions.mjs` 由完整回归调用，定向筛选使用 `TEST_FILTER='Performance'`。输出 `performance-operations.json` 和六种宽度的截图，均写入 `TEST_OUTPUT_DIR`。报告记录操作系统、CPU、Node、浏览器版本，以及同一浏览器的三组前后数据：八阶单位分别为 1、1e1000、1e100000，资源分别为 1e6、1e10000、1e1000000。这些是明确设置破界历史的人工资源夹具，不是三个真实后期阶段存档。

每组检查资源文本和原快照一致、名册八阶数字一致、代表精灵不超过24个；记录页面节点数、名册点击到可见的端到端时间、外壳和内核各60个动画帧间隔，以及20次原版50ms模拟步的实际计算耗时。在线计时器停止，模拟步由测试显式执行；动画帧采样与模拟步计时分开，不能据此推断持续生产、自动化或所有后期系统满负载的帧率。测试不设随机器负载波动的FPS门槛，原始时间保留用于同环境比较。

随后在320/375/414/768/1024/1440宽度实际打开名册，检查页面无横向溢出、名册数字没有被自身容器裁切，并保存截图。第012轮人工查看320截图曾发现购买行指数与价格重叠；第013轮将窄屏的单位名称、数量、价格放入独立网格行，保留按钮和肖像各自的列。测试新增八阶行各单元互不重叠、文字矩形位于所属单元内的断言，并在每种宽度实际购买第一阶，确认购买计数增加。

截图等待夹具批量解锁产生的通知按原计时自然消失，不隐藏通知或改变其原生命周期。六宽度定向检查通过；人工复查320/768/1440截图确认购买行大数分开显示。320资源头部仍会换行，阶段重置入口及其他后期界面仍有中英混排和样式问题；该测试不覆盖通知密集出现期间的所有按钮可达性，也不代表全部后期大数界面均已验收，AC12仍不能标为PASS。

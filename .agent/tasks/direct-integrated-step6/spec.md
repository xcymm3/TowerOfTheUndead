# 第六步：存档与整体验收规格

任务 ID：`direct-integrated-step6`

状态：已冻结（2026-09-18）

## 范围

在不改变原版玩法、数值、767 条映射、存档语义、自动化脚本语法和发布标准的前提下，补齐历史及损坏存档、全部备份类型、长离线、跨阶段操作链、持续运行和大数显示验证，并在当前最终源码上集中执行完整回归。第六步只完成本地与正式产物验收；不运行 Deadline-Carl，不部署 GitHub Pages，原验收标准 AC15 的线上部分留待第七步。

## 验收条件

### AC-1：历史、损坏与跨阶段存档

- 验证旧根结构与旧序列化格式可迁移，并以当前阶段存档语料覆盖初期、中期、创世、主宰和终局代表状态。
- 验证损坏主存档、损坏备份、无效文本/伪装存档不会污染当前有效状态，并能从有效备份恢复。
- 验证三个手动存档槽、刷新重载和主题/原版命名空间隔离；可比较行为必须与原版一致。

### AC-2：全部备份类型与备份归档

- 覆盖 1、5、20、60 分钟在线备份，10 分钟、1 小时、5 小时离线备份和保留备份共 8 个槽位。
- 在线、离线、保留三种类型均须通过实际界面完成代表性恢复；8 个槽位均须验证保存内容和恢复结果。
- 验证全部备份导出文件、清空后导入、备份时间恢复和损坏备份归档拒绝路径。

### AC-3：长离线

- 验证至少 24 小时与 7 天离线，覆盖启用、禁用、跳过/加速控制和代表性后期状态。
- 离线所得、时间推进、备份触发和恢复后状态必须可解释，与原版同输入结果一致。
- 测试须有明确超时和离线 tick 上限，不得因模拟导致挂起。

### AC-4：跨阶段操作链

- 通过真实界面或原版公开操作入口验证“新存档到首次转生”“中期到创世”“主宰到终局”三条连续操作链。
- 为达到边界使用的夹具必须在报告中披露；边界动作、解锁和重置不得通过直接设置完成标志替代。
- 每条链记录关键动作、前后状态与主题/原版一致性结果。

### AC-5：持续运行与大数显示

- 在实际游戏循环启用时执行有界持续运行，记录帧响应、错误、DOM 节点、动画/精灵数量和资源增长。
- 覆盖普通数、超大数和后期代表页面；数值必须可读，不得出现 `NaN`、`undefined`、未解释的 `Infinity`、裁切或不可操作控件。
- 六档宽度的既有界面检查继续通过，持续运行不得出现挂起或无界节点/精灵增长。

### AC-6：完整回归与正式产物

- 当前最终源码通过源码校验、类型检查、lint、全部功能测试、主题/原版双构建和正式产物冒烟。
- 正式产物须验证 `/TowerOfTheUndead/` 子路径、资源无 404、购买、军团同步、保存刷新和版本/哈希一致性。
- 正式产物不得包含参考工程、测试、私有证据或许可要求之外的开发文件。

### AC-7：原 15 项标准本地复核

- 对原 AC1 至 AC14 的本地部分逐条给出 `PASS`/`FAIL`、证据和说明，不得仅以一次总测试概括。
- 原 AC15 明确标记为 `DEFERRED_TO_STEP7`，不得在未发布时宣称通过。
- `evidence.md`、`evidence.json`、`verdict.json`、`problems.md` 和原始报告须对应本规格全部 AC，且来自同一最终源码的新鲜运行。
